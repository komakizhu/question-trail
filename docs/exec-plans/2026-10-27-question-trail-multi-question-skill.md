# 题迹多题型与 Markdown 整理 Skill 执行计划

## 目标与边界

在 `codex/question-trail-task` 实现单选、多选、判断、主观题练习，以及可预览、批量应用和验证的题迹 Skill。所有修改留在当前 worktree；不安装到用户实际库或全局 Skill 目录，不提交、合并、推送、发布，不改公考批改 Skill。

保留现有 `exam-question` / `exam-material` Callout、块编号、V1/V2 作答数据、批改同步、Markdown 原文和保存失败保护。新增存储使用 `questionTrailV3`。

## 共享格式约定

- 题目使用现有 Callout 与块编号；块编号后增加 `题型：单选`、`题型：多选`、`题型：判断` 或 `题型：主观题`。材料、标签和关联仍用现有文本与双链约定。
- 单选/多选选项用顺序字母 A–Z；判断题保留原有选项文字，答案按题内显示选项映射；主观题不解析选项。
- 内部统一使用 `QuestionKind = single | multiple | judgment | subjective`，选项标识为 `A`–`Z`。作答的 `selected` 和快照 `answer` 均为标识数组；`answer: null` 表示无可用参考答案。每条记录保存 `kind`。
- 新题须有明确题型。无题型的旧四选项块继续作为单选兼容；其他无类型结构不猜类型。无参考答案与空作答分别保存，不自动判分。
- Skill 的操作范围只来自显式指定的 Markdown 文件；预览确认后，对文件逐个复查源文，变化时停止并要求重新预览。应用逐文件原子替换并报告部分失败。

## 全局约束

- 仅在此 worktree 和当前分支修改；保留原始 V1/V2 记录，不自动迁移/覆盖用户 Markdown。
- 每个插件功能阶段完成后运行完整 `npm run build`；失败则先修复。
- 不修改其他仓库，不安装到真实库/全局 Skill，不提交、合并、推送或发布。
- 自动化和 Obsidian 检查使用隔离数据，不写用户笔记。

## Tasks

### Task 1: 题型解析与历史

扩展 Markdown 题目模型和答案集合；新增 V3 记录读取/写入，惰性保留 V1/V2；兼容旧导入格式且不扩展上游导出；覆盖多选集合、无答案、保存失败和重命名。运行对应测试并完整构建。

### Task 2: 题目交互与题组

单选/判断互斥选择，多选独立勾选；逐题提交；主观题可无标记完成；保存当次参考答案与标记；正确、错选、漏选和不确定同时清晰呈现。重做隐藏个人提示但保留题干和材料，混合题组逐题计次。运行渲染和存储检查并完整构建。

### Task 3: 题迹 Skill

创建 `skills/question-trail`，提供版本 5 双语元数据、中文操作说明、格式样例，以及标准库 Python 的 `inspect`、`preview`、`apply`、`verify` 入口。支持多文件预览、歧义列出、稳定编号、幂等整理、源文变化阻断、逐文件应用和失败报告。按 Skill 测试样例运行脚本，复核插件解析可识别其输出，并完整构建。

### Task 4: 联合验收与包

运行 `npm test`、`npm run test:study`、`npm run test:obsidian` 和 `npm run build`；在隔离样例中核对真实 Obsidian 渲染和 Skill 操作；检查浅/深色、题组折叠、重载、源文保留、包内容、Git 状态和完整差异。

## 验证、兼容与回滚

- 每个插件功能阶段后都完整构建；构建失败先修复，不能进入下一阶段。
- 扩展测试覆盖 A–Z、多选错选/漏选、判断原文、主观空标记完成、无参考答案、旧数据迁移、损坏 V3、保存失败、重复块编号、混合题组与提示隐藏。
- Skill 验收覆盖多文件一次预览/确认、重复运行无差异、编号保留、代码块/表格/公式中的伪选项、源文件预览后变化、单文件写入失败和包内独立运行。
- V1/V2 原字段保持不变。恢复旧插件时不删除 V3 数据；旧版仅读取自身格式，新版恢复后继续读取 V3。不得把降级期间旧格式的写入与 V3 静默合并。
- 所有集成/运行测试使用隔离 DOM、内存存储或临时 Markdown，不改用户笔记和作答数据。
